## Результат

Приложение для управления задачами с хранением данных в памяти текущей страницы реализовано полностью. Выполнены сценарии:

- отображение задач и названий категорий (12 задач, 3 категории);
- создание задачи с проверкой полей (название 1–100 символов после trim, допустимый приоритет, существующая категория);
- редактирование с сохранением `id` и `completed`;
- переключение статуса и удаление после подтверждения;
- совместное применение поиска и фильтров статуса, приоритета и категории;
- общая статистика по полному набору и число найденных записей;
- понятное пустое состояние при отсутствии совпадений.

**Ограничение:** данные хранятся в памяти страницы. Перезагрузка восстанавливает исходный набор из `src/data.js` и начальные фильтры варианта — это ожидаемое поведение ПР7

## Компоненты и состояние

- `App` — `tasks`, `filters`, `editingId` (три `useState`);
- `TaskForm` — локальные `draft` и `errors` (и `message` для сообщения о результате).

Передача данных и обратных вызовов:

- `App` передаёт вниз `tasks` (уже отфильтрованные), `filters`, `categories`, `initialTask`, `stats`;
- действия сообщаются наверх через колбэки: `onToggle(id)`, `onEdit(id)`, `onDelete(id)`, `onSave(value)`, `onCancel()`, `onChange(nextFilters)`;
- `TaskItem` не хранит копию задачи: при изменении props он отображает актуальные данные родителя.

Производные данные считаются в рендере `App`, без отдельных `useState`/`useEffect`:

- `visibleTasks = selectTasks(tasks, filters)`;
- `stats = getTaskStats(tasks)`;
- `editingTask = tasks.find(t => t.id === editingId) ?? null`.

## Контрольные вопросы

JSX vs HTML-строка: JSX — это синтаксис в JS, который превращается в вызовы React, а не в строку. Внутри работают {}, атрибуты className/htmlFor.

Props vs состояние: props приходят от родителя и только для чтения; состояние своё, меняется через useState и вызывает перерисовку.

Почему не обычная переменная: она сбрасывается при каждом рендере и не сообщает React об изменениях.

Когда функциональное обновление: когда новое значение зависит от предыдущего: setTasks(prev => ...).

Почему нельзя мутировать объект в копии массива: копия хранит те же ссылки; мутация меняет исходные данные, и React не увидит изменений.

Зачем key: чтобы React различал элементы при удалении/перестановке. Индекс не подходит — он смещается.

Почему выборка и статистика не в состоянии: это производные данные; их пересчёт в рендере всегда актуален.

Как дочерний сообщает о действии: через колбэк из props (onToggle(id)).

Управляемое поле: получает value из состояния и обновляет его через onChange.

Почему categoryId преобразуется: <select> возвращает строку, а в схеме число. Проверка строгая (/^\d+$/).

Что делает key у формы: при смене ключа компонент пересоздаётся и локальное состояние сбрасывается.

Почему confirm не в setTasks: функция обновления должна быть чистой; confirm — побочное действие, а StrictMode может вызвать updater дважды.

Пустые задачи vs пустая выборка: смотрим на tasks.length и текст пустого состояния; статистика считается по полному набору.

Что проверяет npm test: контракты чистых функций (28 кейсов). Не проверяет React и UI — для этого ручной протокол.

Что менять для API в ПР8: заменить локальные операции на асинхронные HTTP-вызовы, добавить загрузку/ошибки, onSave → Promise<boolean>, useEffect для загрузки.
